# Sample data — GENERATED ONLY

This project **never** ships real personal photos or memories. Every demo input
here is machine-generated. There are two sources, and neither is a real person's
photograph.

## 1. Programmatic synthetic photos (default)

Drawn at runtime by [`src/cinemory/synthetic.py`](../src/cinemory/synthetic.py)
(Pillow gradients + shapes, deterministic per seed). This is what the tests, the
offline pipeline and the app's *"Try with sample photos"* button use.

To materialise a set on disk:

```bash
python scripts/generate_demo.py --out sample-data/generated --count 6
```

The output directory (`sample-data/generated/`) is git-ignored.

## 2. `anniversary/` — AI-generated scene photos (committed)

Six photos of an anniversary gathering, used as the input for the demo video so
the finished reel shows a scene rather than a colour gradient.

**How they were made.** Text-to-image through Cinemory's *own* provider adapter:
`GenblazeMediaProvider.generate(modality=IMAGE, model="seedream-5.0-lite")` —
the same `genblaze` SDK and the same GMI Cloud provider family the live product
already uses for video, only a different modality. Each was then centre-cropped
to 16:9 and resized to 1024x576 (matching `synth_photo`'s proven-live default,
which is above Kling's 300px minimum side) and saved as JPEG to keep the repo
small. Total: under 700 KB for all six.

**The people in them are fictional and model-generated.** No photograph of any
real person was used as input, reference or output, and nothing here depicts or
is intended to resemble a specific real individual. They are prompt-generated
scenes: a doorway welcome, a laid table, a toast, a cake being cut, a sofa after
dinner, a couple at the end of the night.

**Licence.** Generated by this project, for this project, and covered by the
repository's MIT licence like every other demo asset. There is no third-party
stock photography anywhere in this repo, so there is nothing to attribute.

**Provenance stays honest.** These are pipeline *inputs*, not outputs. The
manifest records them exactly as it records any input — by SHA-256, cited from
each step's `source_sha256s`. The manifest has no field that claims an input is
a real user's upload, and nothing was added to imply one.

> `.gitignore` still blocks `*.jpg` everywhere as a PII safety net; this
> directory is the single, deliberate exception, alongside `private/` and the
> other blocked photo formats which remain blocked.
